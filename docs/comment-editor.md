# 评论表情与 @ 提及

评论表情由服务端目录、文本标记和图片渲染组成。正文保留 `[doge]`、`[笑哭]` 等原始标记，表情图片通过 B 站 CDN 获取；颜文字直接插入文字。表情不是评论附件，不走图片上传接口，也不需要把整套素材打进 APK。

## 数据与缓存

- `CommentEmoteRepository` 使用现有签名 REST 客户端请求 `/x/emote/user/panel?business=reply`，获取当前账号的表情包。
- 用 `/x/emote/package` 补全缺少内容的表情包，以及内置的小黄脸、小电视、喵和颜文字分类。解析服务端名称、图片、尺寸与可用状态，付费包中未解锁的表情禁用。
- 可用状态由单项 `flags.no_access` 判断，缺失时回退到表情包的同名字段，再默认可用。`unlocked=false` 也会出现在免费表情上，不能据此禁用；内置分类同样遵守明确的访问限制。
- 表情目录按 UID 缓存在应用私有 SharedPreferences 中，有效期 6 小时。刷新按钮强制请求；网络失败时允许使用已有缓存。图片复用 `BiliAsyncImage` 的 Coil 内存和磁盘缓存。
- 最近使用按 UID 保存最多 32 个标记，展示时与当前目录重新匹配，过滤已失效或无权限的项目。切换账号会清空正在编辑的草稿和搜索请求。

## 编辑与发送

`CommentEditorState.input` 使用 `TextFieldValue` 保存正文、选区和输入法组合状态。表情在光标处插入，选中文字时替换选区；面板删除键一次删除一个完整的已知表情标记，普通 Unicode 字符按 code point 删除。

工具栏依次是表情/键盘切换、图片和 @，右侧是发送按钮。表情面板用自适应网格，底部切换分类和最近使用。编辑区使用嵌入 Compose 的原生 `EditText`，通过 `ImageSpan` 将标记显示成行内图片，底层文本仍保留完整标记。图片复用应用的 Coil 缓存，并支持异步加载和动图。光标、选区和键盘删除按完整表情处理，输入法正在组合的文字不转换；图片加载失败时恢复可读标记。评论列表继续使用 `CommentRichText`；未知标记保留文字，颜文字保持原样。

原生输入框在硬件加速下会单独缓存文字的绘制结果，图片加载完成后仅调用 `invalidate()` 可能继续显示缓存中的灰色占位。表情 Drawable 的刷新回调按帧合并，通过临时 `UpdateAppearance` 标记使文字缓存失效，覆盖图片加载及动图更新，同时保留正文、选区和输入法组合态。原生测试用延迟返回的图片和实际硬件加速窗口验证这一过程。

点击 @ 或在正文输入独立的 `@` 会打开用户选择面板。面板复用评论输入框的焦点，用户继续在正文输入昵称，避免单独的搜索框在选中用户时触发键盘切换。复用已有 protobuf 的 `bilibili.main.community.reply.v1.Reply/AtSearch`，请求携带当前 UID 和关键词，保留接口返回的最近、关注等分组。搜索延迟 250 毫秒并取消旧请求，错误可重试。

选中用户后，在原选区插入 `@昵称 `，同时记录 UID 和精确文本范围。普通编辑会更新范围；修改或删除提及文本会移除身份关联，避免仅凭正文中另一段同名文字继续通知用户。发送时把仍然有效的提及去重，作为 `at_name_to_mid={"昵称":UID}` 随 `/x/v2/reply/add` 一起提交。表情仍在 `message` 内，图片仍使用原有 `pictures` 上传流程。

已选中的提及作为完整编辑单元处理：光标和选区会对齐昵称边界，软键盘、实体键盘和表情面板的退格均整段删除；若光标位于自动插入的末尾空格后，一次退格同时删除昵称和该空格。只有新输入或粘贴的 `@` 会自动打开用户面板，删除文字不会重新触发搜索。

评论列表从 gRPC/REST 的 `at_name_to_mid` 恢复提及用户，高亮并支持点击打开空间。行内表情与提及共同渲染时保持原文索引，长按仍复制完整原文。

## 验证

```powershell
.\gradlew.bat :feature:comment:testDebugUnitTest :core:comment:testDebugUnitTest :app:assembleDebug
```

单元测试覆盖光标/选区替换、提及范围随编辑移动及失效、重复提及去重、输入法组合态、表情整体删除、Unicode 删除、目录权限与异常数据，以及表情和提及共同渲染时的原文索引。

手动检查：表情与键盘互切、分类与最近使用、断网后重开与重试、@ 搜索与插入、已有图片保留、删除或修改 @ 后的草稿。实际发送与账号通知需要用测试账号完成联调。

接口结构参考 [PiliPlus 的表情目录请求](https://github.com/bggRGjQaUbCoE/PiliPlus/blob/main/lib/http/reply.dart) 和 [评论发送参数](https://github.com/bggRGjQaUbCoE/PiliPlus/blob/main/lib/http/video.dart)，用户搜索使用仓库已有的 `reply.proto` 协议。
